# 游戏化庭院花境设计智能体：产品与视觉提案

日期：2026-10-23。状态：设计提案，等待视觉方向选择；尚未开发网页原型。

本文把首版的创作范围、视觉候选、交互约定和验收标准放在一起。技术部分是建议稿，选定视角与视觉方向后再冻结。概念图用于选择方向，不是已实现的界面，也不是可直接使用的分层植物素材。

## 1. 产品定位与成功标准

让没有专业设计软件经验的人，通过摆放植物、景石和装饰，完成一张自己的庭院花境作品。轻游戏感来自即时摆放反馈、组合探索、可选主题和作品完成感。

核心循环：选择素材 → 放入庭院 → 调整位置与组合 → 保存 → 导出作品。

首版成功标准：

- 六类素材均可加入画布；用户能独立完成移动、旋转、等比缩放和删除。
- 前后叠放可控；连续编辑可以按操作撤销、重做。
- 刷新后恢复当前作品；保存失败明确提示。
- PNG 与作品画面一致；JSON 备份可以重新导入继续编辑。
- 所有可见的核心编辑控件可操作；AI 是否接入有明确状态。

首版面向桌面浏览器，兼顾平板横屏。手机提供紧凑操作布局，但复杂编辑的优先体验是桌面和平板。界面名称暂用“庭间”，可在选方向时替换。

## 2. 首版范围

| 能力 | 首版范围 | 后续扩展 |
| --- | --- | --- |
| 庭院 | 一个固定尺寸、可缩放查看的庭院场景 | 自定义地形、庭院尺寸和多种场景 |
| 素材 | 目标约 30 个统一风格素材，覆盖花卉、灌木、观赏草、树木、石头、装饰 | 更多品种、个人素材上传 |
| 编辑 | 单选、拖放、移动、平面旋转、等比缩放、删除、复制 | 框选、组合、批量调整 |
| 图层 | 前移后移、列表排序、隐藏、锁定 | 图层分组 |
| 历史 | 当前会话最近 50 次有效操作的撤销重做 | 长期编辑历史 |
| 辅助 | 网格显示、独立吸附开关、画布缩放与平移 | 真实尺寸标注、种植间距辅助 |
| 保存 | 当前作品自动保存到本机浏览器；手动保存；JSON 备份与恢复 | 多作品云空间、跨设备同步 |
| 导出 | PNG 成品图、JSON 可编辑文件 | PDF、专业施工图 |
| 游戏模式 | 自由创作；3 个可选主题卡 | 课程任务、挑战进度与更多主题 |
| AI | 预留模块接口；界面说明“后续接入” | 真实推荐、分析、建议预览与应用 |

不把金币、商城、养成计时或排行榜加入首版。所有首版素材直接可用。主题挑战不锁定自由创作。

## 3. 视觉方向与取舍

三张候选已独立生成并在聊天中显示。实际显示顺序与本地文件如下：第 1 张为 [自然花境](directions/natural-garden.png)，第 2 张为 [治愈拼景](directions/painted-courtyard.png)，第 3 张为 [植物手帐](directions/botanical-notebook.png)。原始生成提示词保存在 [视觉生成记录](2026-10-23-image-prompts.md)。

| 方向 | 画面与布局 | 适合的体验 | 主要取舍 |
| --- | --- | --- | --- |
| 苔庭 · 自然花境 | 固定俯视，自然植物切图、苔绿与石灰色；底部素材架，选中对象旁出现小工具条 | 沉浸摆放，先看花园再看工具 | 植物高度以属性表达，不显示真实立面 |
| 小庭日和 · 治愈拼景 | 固定斜俯视的 2D 手绘庭院；右侧轻量素材抽屉，底部对象调整条 | 更接近休闲庭院装饰游戏 | 植物立面图片不能冒充真实三维转向；自由旋转需调整素材方案 |
| 四季花笺 · 植物手帐 | 清晰的俯视种植构图，植物形态更具插画感；大画布，按需打开素材浮层与植物资料 | 配色与布局探索，适合入门教学 | 更像创作手帐，场景沉浸感较弱 |

建议优先固定俯视方向。它与“任意平面旋转、自由叠放、可预测导出”最一致。若选择斜俯视，应先明确：旋转是二维贴图旋转，还是需要多角度植物素材；后者增加素材生产量，不能通过旋转一张树木图片实现。

实际概念图均带有一定场景透视，第二张尤其明显。它们用于确定画风、场景感与控件布局；进入开发前仍需统一可编辑素材的视角，并验证代表素材的旋转效果。图中的完整庭院背景不能当作所有植物都可拆开编辑的现成资源。

所有方向共同遵守：

- 不设置复杂左侧导航；顶部只保留作品名、模式、保存状态和导出入口。
- 画布是最大区域；桌面初始布局中，庭院编辑区约占视口面积的三分之二或更多。
- 森绿作为操作强调色，低饱和花色作为作品内容；界面不能抢过植物。
- 正文与控件文字以 14–16px 为基准；操作图标提供文字提示，触控不依赖悬停。
- 浮层使用轻边界与少量阴影，不把每一项功能堆成卡片。
- 动效仅用于放置、选中和面板切换；遵守减少动态效果偏好，不使用持续摇摆干扰精确操作。

## 4. 页面结构与主要流程

### 4.1 初次进入与继续创作

1. 有有效本地作品时直接恢复，并显示作品名和保存状态。
2. 没有作品时打开带基础地面的空庭院，显示一条短提示“从植物库拖入，也可点选后放置”。
3. 自由创作立即可用。示例作品从作品菜单载入；已有编辑时先提供保存备份入口，避免静默覆盖。
4. 顶部作品菜单包含新建、导入 JSON、下载 JSON；不另建复杂首页或作品管理系统。

### 4.2 素材选择与放置

- 分类是花卉、灌木、观赏草、树木、石头、装饰。搜索与筛选按需展开。
- 筛选维度包含主要颜色、株型、观赏季节、高度等级；不同维度取交集，同一维度多选取并集。
- 植物资料中展示名称、标签与简短说明；高度与季节来自素材目录，未核实的内容标明“待核实”。
- 鼠标可以从素材库拖入庭院，移动时出现半透明预览；在有效区域松开才创建对象。
- 支持“点击素材 → 点击庭院放置”作为触屏及拖拽的替代方式；放置一次后返回选择工具。
- 在庭院外松开或按 Esc 取消放置，不创建对象、不产生撤销记录。
- 同一素材可以多次放入，实例拥有独立位置、比例和图层。

### 4.3 单对象编辑

- 点选显示细边框、旋转手柄和等比缩放手柄；空白处点按取消选择。
- 拖动保留抓取位置偏移，对象不能突然跳到鼠标中心。
- 俯视方向支持 0–359° 平面旋转；比例暂定 40%–200%，只代表画面大小，不宣称真实冠幅。
- 对象锚点保持在庭院范围内，叶片边缘允许越界；画布与导出按相同庭院边界裁切。
- 选中后可复制、删除、前移、后移。重叠对象可从图层列表精确选择。
- Delete 删除选中对象；Ctrl/Cmd+Z 撤销；Ctrl/Cmd+Shift+Z 重做；输入作品名时不拦截文本编辑快捷键。
- Esc 或指针取消恢复本次拖动前的状态；一次拖动、旋转或缩放只记录一次历史操作。

### 4.4 图层、网格与查看

- 图层面板从画布角落的按钮展开，平时收起；不永久挤占画布。
- 列表最上方对应最前面的对象；手动排序为最终顺序，不同时自动按纵坐标重排。
- 锁定对象不能在画布上变换；隐藏对象不显示、不参与画布命中、不出现在 PNG 中。
- 网格显示与吸附分开控制。吸附只改变当前编辑对象的锚点，不批量移动已有对象。
- 查看比例支持适应画布和 50%–200%；缩放与平移只改变视口，不修改作品坐标。
- 平移工具可以拖动画布空白区域；桌面也可用空格临时平移。平板通过明确的工具切换，避免单指操作歧义。

### 4.5 保存、恢复与导出

- 有效编辑提交后短延迟自动保存；“保存”按钮立即保存当前状态。必须写入成功才显示“已保存到本机”。
- 撤销或重做后的场景同样自动保存；刷新恢复的是最后成功保存的当前作品。
- 原型只恢复作品，不恢复上次会话的撤销历史。
- JSON 用于可编辑备份；导入先验证版本、对象数据和素材引用，验证失败保留当前作品。
- 导入成功作为一次可撤销操作。新建、载入主题也作为一次可撤销的场景替换操作。
- PNG 默认 1600×1000，与逻辑庭院比例一致；包含地面和可见素材，不含选择框、网格、手柄和操作界面。
- 导出前等待素材加载完成；加载失败时指出失败素材并允许重试，不输出缺植物的“成功图片”。
- 存储失败显示“未保存到本机”，保留编辑状态，并提供 JSON 下载。损坏的本地作品不自动覆盖为空场景。
- 同一浏览器标签来源内保存；清除浏览器数据或更换来源会影响恢复。使用本地 HTTP 服务或静态站点运行，不把双击 HTML 作为保存可靠性的验收方式。

## 5. 游戏化与 AI 边界

主题卡首版拟定为“白绿静庭”“紫色夏日”“石与草的留白”，每张提供一段创作目标与可选初始布局。名称是创作主题，不代表植物物候已验证。

用户可随时退出挑战继续自由编辑。首版只显示创作目标，不以未经验证的自动分数判断设计优劣，不制造虚假的专业评价。

AI 模块后续接收：用户目标、场景 JSON、当前可用素材目录和用户主动提供的环境条件。输出：推荐的素材 ID、组合说明、配色建议及可选布局补丁。

AI 接入前不使用预写文案伪装实时分析。接入后，建议先预览，再由用户点击应用；一次应用对应一次可撤销操作。推荐只能引用有效素材 ID。地区适应性、光照、水分、物候及种植间距需要可靠植物资料支持，不能从画面推断为已验证的园艺结论。

## 6. 技术方案建议

### 6.1 技术路线比较

| 路线 | 优点 | 代价 | 本项目建议 |
| --- | --- | --- | --- |
| HTML/CSS + SVG 场景 + ES Modules | 对象变换与选中关系直观；无须先搭游戏引擎；便于扩展本地素材目录 | 大量复杂节点时需要测量性能；透明素材命中需处理 | 首版采用 |
| Canvas 2D 自绘编辑器 | 集中控制绘制与像素导出，适合大量对象 | 需自行实现命中、选框、变换与重绘 | 对象规模或动效需要时再评估 |
| 2D 游戏引擎 | 资源和动画机制完整 | 首版会引入并不需要的场景、生命周期与构建复杂度 | 当前不采用 |

SVG 支持平移、缩放与旋转；此处选择 SVG 是针对本项目对象编辑规模的工程判断。[SVG transform 文档](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/transform)

### 6.2 模块边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| 素材目录 | ID、图片路径、标签、默认大小、锚点和授权信息 | 当前作品内的对象位置 |
| 场景状态 | 对象实例、顺序、属性及数据验证 | DOM 节点和临时选框 |
| 场景渲染 | 根据状态更新 SVG，独立绘制编辑辅助层 | 保存与业务历史 |
| 指针交互 | 放置、选择、拖动、缩放、旋转、坐标转换 | 直接写本地存档 |
| 历史记录 | 保存有效操作前后快照，管理撤销重做 | 每个 pointermove 的中间状态 |
| 存储与导出 | 本地读写、JSON 往返、PNG 输出 | 植物推荐 |
| 界面 | 素材库、面板、状态提示与模式入口 | 作为作品数据来源 |
| 主题与 AI 接口 | 主题配置；未来的分析和布局建议入口 | 直接绕过历史修改场景 |

状态提交是唯一入口：交互预览 → 提交有效变更 → 历史记录 → 渲染与保存。选择对象、打开面板、移动视口是界面状态，不写入作品历史。

Pointer Events 统一鼠标与触控；指针捕获保证拖出对象边界后仍能完成操作，并处理取消事件。[Pointer Events 文档](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

### 6.3 数据约定建议

固定逻辑场景 1600×1000。所有对象都存逻辑坐标，浏览器尺寸和查看比例通过坐标转换处理。

场景：`schemaVersion / assetCatalogVersion / title / sceneSize / backgroundId / mode / challengeId / updatedAt / objects[]`。

实例：`id / assetId / x / y / rotation / scale / visible / locked`。数组顺序表示从后到前，不再保存另一套 zIndex。

素材：`id / name / category / image / thumbnail / baseSize / anchor / colors[] / habit[] / seasons[] / heightBand / description / source / license / metadataStatus`。

图片是本地静态资源，不写进 localStorage。首版采用有上限的场景快照历史，避免先引入复杂命令框架。用户上传素材和云端保存出现实际需求时，再调整存储结构。

### 6.4 保存与 PNG 导出约束

- 当前作品存 localStorage；JSON 文件是用户可自行保管的备份。图片继续由素材目录引用。
- localStorage 可能被浏览器策略禁用；`file:` 来源下的行为没有可靠统一保证。[localStorage 文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)
- PNG 使用只含作品内容的 SVG 副本，将素材嵌入后栅格化至 Canvas，再导出 Blob。变换、顺序与裁切复用同一份场景定义。
- 素材统一随项目发布；不依赖任意外链图片。未经允许的跨域图像会导致 Canvas 无法导出像素数据。[Canvas 跨域图片文档](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image)
- 实施时先用一小组代表素材验证完整链路，再制作其余素材；避免图做好后才发现裁切、锚点或导出不一致。

## 7. 素材制作规范

- 同一视觉方案内统一视角、光向、柔和阴影与画风；植物采用透明 PNG/WebP，禁止用整张设计效果图替代可编辑对象。
- 庭院地面与可编辑物件分开；素材缩略图与画布资源引用同一素材 ID。
- 去除过大透明留白，统一登记锚点与默认显示大小；素材轮廓与选择命中保持一致，避免透明边角挡住其他植物。
- 第一组代表素材覆盖一株花卉、灌木、草、树、景石和装饰，验证摆放及遮挡后再扩至目标数量。
- 每个素材记录来源和使用授权；生成式素材标明生成来源。植物标签是独立数据，不能因图像看似某物种就当作准确鉴定。
- 季节筛选表示素材标签，不模拟四季生长；高度分类不等于真实比例或施工尺寸。

## 8. 第一版实施顺序与验收

以下是方向选择后的阶段计划，当前未执行。

1. **冻结画布和代表素材** → 验证：确定俯视或斜俯视；6 类代表对象具备一致视角、透明背景和有效锚点；完成一次 SVG 到 PNG 的概念验证。
2. **实现编辑主链路** → 验证：新增、移动、旋转、缩放、复制、删除和前后叠放可用；缩放视口后拖拽不偏移；取消操作不残留对象。
3. **实现历史与保存** → 验证：完整编辑序列可逐步撤销重做；新操作清空旧重做分支；刷新恢复当前作品；模拟保存失败时状态明确。
4. **完成素材与模式** → 验证：六类素材可筛选、重复放置；组合筛选结果正确；主题卡可进入退出；自由创作不受限。
5. **完成导出与浏览器验收** → 验证：PNG 与当前作品一致；JSON 导出导入可继续编辑；桌面与平板布局、鼠标与触控替代操作通过实际浏览器检查。

关键验收用例：

| 场景 | 通过标准 |
| --- | --- |
| 连续编辑 | 添加 → 拖动 → 旋转 → 缩放 → 排序 → 删除，再逐步撤销重做，数据和画面对应 |
| 单次操作 | 一次连续拖动只需撤销一次；Esc/pointercancel 不产生多余历史 |
| 历史分支 | 撤销后新增对象，旧的重做分支清空 |
| 重叠选择 | 前后顺序稳定，透明留白不会持续阻挡选择；图层列表可定位每个对象 |
| 图层状态 | 隐藏对象不导出；锁定对象不能被误拖；恢复后状态保留 |
| 坐标转换 | 适应画布、100%、200% 下相同拖动行为没有落点漂移 |
| 刷新恢复 | 变换、顺序、隐藏、锁定和作品名完整恢复；撤销后刷新恢复撤销后的状态 |
| JSON 往返 | 导出 → 新建 → 导入，状态一致；错误版本或损坏文件不覆盖当前作品 |
| PNG | 透明边缘、旋转、缩放、重叠和越界裁切正确；无选框、网格或工具栏 |
| 失败状态 | 存储不可用、图片失败、损坏 JSON 有明确结果，不假报成功 |
